3. PROPOSED_ARCHITECTURE (MINIMALIST & NATIVE-FIRST)
Arsitektur termurah, paling andal, dan zero-heavy-dependency:
- Skrip diagnostik tunggal: /home/ubuntu/Polya-AI/scripts/ops/polya_health_watchdog.py (Python stdlib: urllib, sqlite3, subprocess, json).
- Eksekusi berkala: systemd timer (polya-watchdog.timer) setiap 2 menit atau cron job terisolasi.
- State Tracking & Anti-Flapping: File JSON lokal (/home/ubuntu/.polya/watchdog_state.json) menyimpan counter kegagalan dan status alert aktif.
- Notifikasi Dispatcher: Webhook generik (Telegram Bot API / Discord Webhook / WhatsApp via local service) yang dipicu hanya saat transisi state (OK -> DEGRADED/DOWN dan sebaliknya).

4. ALERT_RULES_AND_THRESHOLDS
- P0: SERVICE_DOWN
  * Pemicu: polya-web.service inactive/failed ATAU http://127.0.0.1:8000/api/arena/state gagal 2x berturut-turut (interval 10 detik).
  * Cooldown / Deduplikasi: 15 menit per alert. Pemulihan dikirim saat status kembali 200 OK.
- P1: HTTP_DEGRADED / 5XX_SPIKE
  * Pemicu: 3 endpoint inti (/api/arena/state, /api/v1/themes, /api/v1/calculator/source) merespons non-200 atau latensi > 2.500 ms selama 3 run berturut-turut.
  * Cooldown: 30 menit.
- P2: DB_INTEGRITY_FAIL
  * Pemicu: PRAGMA integrity_check mengembalikan selain "ok" pada polya_arena.db.
  * Level: CRITICAL langsung tanpa delay.
- P3: BACKUP_MISSED
  * Pemicu: File backup produksi berumur > 26 jam.
