1. VERIFIKASI VARIABEL ENVIRONMENT PRODUKSI & DEPENDENSI APLIKASI
================================================================================
A. Inventarisasi Kebutuhan Environment Runtime (polya-web.service):
   1. POLYA_ENV:
      - Wajib disetel ke: "production"
      - Mengunci GoogleAuthVerifier.is_mock_allowed() agar SELALU bernilai False.
   2. GOOGLE_CLIENT_ID:
      - Wajib disetel ke: "953116755250-qomlk1eh2q01u62nlfemm68td1ca2bbu.apps.googleusercontent.com"
      - Sesuai dengan Client ID resmi pemilik untuk domain https://apologets.com.
   3. POLYA_AUTH_SECRET:
      - Wajib diisi string rahasia acak 64 karakter heksadesimal (32 bytes entropy).
      - Di-generate via pustaka standar `secrets.token_hex(32)`.
      - Wajib unik, tidak boleh menyalin secret staging, dan tidak boleh terpapar.
   4. POLYA_DB_PATH:
      - Jalur database produksi yang terisolasi dan aktif secara default:
        /home/ubuntu/Polya-AI/data/polya_arena.db
      - Menjaga isolasi dari staging (yang menggunakan polya_arena_staging.db).
   5. Konfigurasi Pembayaran Midtrans:
      - File .env.production WAJIB mempertahankan variabel MIDTRANS eksisting:
        * MIDTRANS_CLIENT_KEY
        * MIDTRANS_SERVER_KEY
        * MIDTRANS_IS_PRODUCTION
      - Dengan memasukkan variabel ini secara eksplisit ke dalam .env.production,
        transaksi pembayaran dan verifikasi signature webhook Midtrans tetap berjalan
        sempurna tanpa kehilangan konfigurasi.
   6. Dependensi AI & TTS:
      - NINE_ROUTER_URL default: http://localhost:20128/v1/chat/completions (9router aktif).
      - GEMINI_API_KEY dimuat mandiri oleh app.py dari /home/ubuntu/.env.gemini jika diperlukan.
      - Tidak ada dependensi yang hilang atau terdistorsi oleh penerapan .env.production.

3. ANALISIS GENERASI SECRET, PERMISSION, DAN INTEGRITAS SESI
================================================================================
A. Standar Kriptografi POLYA_AUTH_SECRET:
   - Dibuat menggunakan CSPRNG Python `secrets.token_hex(32)`.
   - File .env.production dibuat dengan permission ketat 0600 (-rw-------),
     dimiliki oleh user:group `ubuntu:ubuntu`.
   - Secret DILARANG keras dicetak ke stdout, journal log, terminal, atau audit doc.

B. Konfirmasi Dampak Terhadap Sesi Pengguna:
   1. Sesi Google Authenticated:
      - Sebelum perbaikan ini, seluruh login Google di production menghasilkan HTTP 401
        karena ketiadaan GOOGLE_CLIENT_ID. Dengan demikian, BELUM ADA sesi login Google
        yang tersimpan di tabel arena_users production.
      - Pemasangan POLYA_AUTH_SECRET tidak akan merusak sesi Google yang sedang berjalan
        karena belum pernah ada sesi Google yang berhasil diterbitkan.
   2. Sesi Guest Anonymous ("guest_user"):
      - Permintaan tanpa Authorization header dan berstatus "guest_user" diverifikasi
        secara stateless oleh verify_user_access(), sehingga TIDAK terpengaruh oleh secret.
   3. Sesi Guest Ber-token (guest_<uuid>):
      - Frontend ensureGuestSession() menangani token expired/invalid secara elegan:
        jika token gagal diverifikasi, frontend secara otomatis memanggil POST /api/v1/auth/guest
        untuk mendapatkan token baru yang valid tanpa mengganggu pengalaman pengguna.
   4. Kesimpulan: ZERO DATA LOSS, ZERO BREAKAGE pada database atau sesi pengguna.

4. TINJAUAN SYSTEMD UNIT & READ-ONLY INSPECTION RUNTIME
================================================================================
A. Konfigurasi Unit /etc/systemd/system/polya-web.service:
   - Direktif yang akan ditambahkan:
     EnvironmentFile=/home/ubuntu/Polya-AI/web/.env.production
   - User: ubuntu
   - WorkingDirectory: /home/ubuntu/Polya-AI/web
   - ExecStart: /home/ubuntu/venv/bin/uvicorn app:app --host 0.0.0.0 --port 8000 --proxy-headers --forwarded-allow-ips="*"
   - Restart: always (RestartSec=3)

B. Izin Baca Service:
   - Karena polya-web.service berjalan di bawah User=ubuntu, permission 0600 pada
     /home/ubuntu/Polya-AI/web/.env.production menjamin uvicorn dapat membaca file
     tanpa membuka akses ke pengguna non-privilese.

5. BATASAN ROLLBACK & PERLINDUNGAN DATABASE
================================================================================
A. Aturan Mutlak Rollback:
   - Rollback HANYA mencakup reversi konfigurasi systemd dan file environment.
   - DILARANG melakukan restore database secara otomatis apabila terjadi kegagalan health check.
   - Basis data SQLite (/home/ubuntu/Polya-AI/data/polya_arena.db) sepenuhnya terlindungi dari
     modifikasi, truncate, atau restore yang tidak disetujui.

B. Prosedur Reversi Konfigurasi:
   1. Hapus baris EnvironmentFile dari /etc/systemd/system/polya-web.service.
   2. `sudo systemctl daemon-reload`
   3. `sudo systemctl restart polya-web.service`
   4. Kembalikan unit ke kondisi clean state awal.
