2. REPRODUCTION EVIDENCE & ROOT CAUSE ANALYSIS (HTTP 401 & REPEATED CLICK)
--------------------------------------------------------------------------------
A. Symptom Observed on Production (https://apologets.com):
   1. Tombol Login dengan Google terlihat dan bisa diklik.
   2. UI sempat menampilkan status "Memverifikasi...".
   3. Login berakhir dengan HTTP 401:
      "Authentication failed: valid Google credential required"
   4. Pengguna tetap berstatus Guest Researcher.
   5. Klik berikutnya pada tombol login tidak memunculkan account picker Google.

B. Root Cause Breakdown across Auth Pipeline:

1. Inisialisasi Google Identity Services & Callback:
   - GIS diinisialisasi dengan Google Client ID produksi via `getGoogleClientId()`:
     `953116755250-qomlk1eh2q01u62nlfemm68td1ca2bbu.apps.googleusercontent.com`.
   - Callback `handleGoogleCredentialResponse(resp)` menerima ID token RS256 yang valid dari Google pada `resp.credential`.
   - Frontend mengupdate UI ke "⌛ Memverifikasi..." dan mengirim payload.

2. Payload Frontend vs Skema Backend:
   - Frontend mengirim:
     `POST /api/v1/auth/session`
     Headers: `{"Content-Type": "application/json"}`
     Body: `{"credential": "<GOOGLE_ID_TOKEN>", "is_mock": false}`
   - Backend `web/api_foundation.py` mendefinisikan:
     `class SessionAuthRequest(BaseModel): credential: Optional[str] = None; is_mock: bool = False`
   - Kontrak payload antara frontend dan endpoint backend sinkron dan valid (tidak ada mismatch field atau skema).

3. Backend Verification Failure (Akar Masalah HTTP 401):
   - Endpoint backend mengekstrak `req.credential` dan memanggil `GoogleAuthVerifier.verify_credential(credential)`.
   - Di dalam `GoogleAuthVerifier.verify_credential()`:
     `allowed_auds = cls.get_allowed_client_ids()`
     `get_allowed_client_ids()` membaca `os.environ.get("GOOGLE_CLIENT_ID")`.
   - Pada server produksi (https://apologets.com):
     File konfigurasi produksi `web/.env` TIDAK memuat variabel `GOOGLE_CLIENT_ID` (hanya memuat kunci MIDTRANS).
   - Akibatnya:
     `allowed_auds` bernilai kosong `[]`.
     `GoogleAuthVerifier` mencatat error:
     "GOOGLE_CLIENT_ID is not configured or empty; refusing authentication fail-closed"
     dan mengembalikan `None`.
   - Karena `verified_data` bernilai `None` dan `is_mock` bernilai `false`, backend mengeksekusi:
     `raise HTTPException(status_code=401, detail="Authentication failed: valid Google credential required")`.
   - Token Google yang valid ditolak karena backend produksi tidak memiliki konfigurasi client ID untuk memverifikasi audience secara fail-closed.

4. Kegagalan UI & Tombol Setelah 401 (Repeated Click Failure):
   - Setelah menerima HTTP 401, UI menampilkan alert error dan mereset status, namun pengguna tetap sebagai guest.
   - GIS menandai penolakan/interaksi One Tap dan menetapkan cookie `g_state` (cooldown exponential: 2 jam hingga 1 minggu).
   - Pada klik berikutnya, GIS `prompt()` menekan dialog (`suppressed_by_user`).
   - Tanpa mekanisme `clearGoogleCoolDownCookies()` dan tombol resmi `google.accounts.id.renderButton()`, pengguna tidak dapat login kembali.
